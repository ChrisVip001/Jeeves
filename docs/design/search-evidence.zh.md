# 搜索证据核验

一次成功调用不等于读到了原文，读到原文不等于它能证明用户问的结论。首阶段把这三件事拆开，同时保留原有的航班快捷路径。

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| `jeeves-tools` | 通过原有工具注册表执行，另行记录搜索线索，或请求 URL、最终 URL 与正文完整性。HTTP 重定向仍逐跳检查。 | 不通过正文、摘要或模型声称的 URL 补齐回执。 |
| `jeeves-loop::evidence` | 只审查带有完整、绑定正文回执的调用。按适配器给定的实体、记录时效、候选标识和值判定 `Confirmed`、`Conflict` 或 `Insufficient`。 | 不理解航班、商户或软件包，不把抓取时间当作记录生效时间。 |
| `jeeves-loop::run_with_evidence` | 预取可选并走常规工具准入、预算、取消与 checkpoint。硬回答约束也可单独使用，屏蔽模型草稿的流式输出与文本观察事件。 | 不替应用决定何时启用核验，也不把不确定副作用换成普通答复。 |
| `jeeves-app-server::turn::search_policy` | 选择已注册的应用策略。航班适配器负责原有入口、来源/页面规则、航班说明和无座位图时的条件式建议。 | 不把航班业务规则加到执行循环。 |

## 接入下一个场景

1. 由应用生成查询实体和时效规则。比如门店价格用「门店 + SKU + 规格」和本地日期。发布版本用「项目 + 渠道」以及明确的日期窗口。
2. 针对可接受的来源验证最终 URL，并从一个完整记录提取实体、记录日期、候选标识和值。不要跨行或跨页替记录补字段。
3. 把结构化记录交给 `resolve`。错实体、旧日期、未标日期、失败或截断读取不能支持有时效要求的断言。若一个候选满足查询条件，但另一个有效记录对同一候选给出不同值，拒绝确认。多个合格候选也判为冲突，重复读取不投票。
4. 用应用的确定性回答约束处理三个判定。确认只引用支撑记录并保留其适用范围。冲突和证据不足分别说明，不把未找到说成不存在。不要用未约束的模型草稿作为兜底。

## 首阶段边界

线上只迁移原有航班入口，没有给其他问句新增自动触发规则。运行器和证据判定不含 FlightStats 规则，现有航班来源限制和 HTTP 抓取回退保持不变。未匹配座位图时不给排号、座位号或左右侧建议，公开航班详情也不验证用户订单。

MCP 提取结果在严格核验中标为 `Unbound`，其文本仍可供普通搜索上下文使用。

## 研究引用的读取回执

`/web_research` 和 `/deep_research` 使用同一个来源记录入口。搜索阶段可使用 Parallel MCP，选中准备引用的页面后由宿主发起直接 HTTP 读取。只有回执中的请求 URL 匹配、最终 URL 可用且正文完整时，工具才会分配可引用的来源编号。重定向后的最终 URL 用于交付中的引用。查不到正文时，对应问题保持待核实。

深度研究把回执、读取时间、去除宿主提示后的页面正文和 SHA-256 存入任务状态。模型看到的长文预览有单独的长度限制。恢复时重新核对回执和正文哈希，缺回执或哈希不匹配的旧来源退出引用候选，保留原编号供历史消息对照。

这一步覆盖来源和逐字摘录。实体、日期和结论之间的关系仍由场景适配器检查。对于开放式研究，运行时交付可复核的摘录和未解决的问题。
