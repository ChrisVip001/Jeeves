# 搜索证据核验

一次成功调用不等于读到了原文，读到原文不等于它能证明用户问的结论。首阶段把这三件事拆开，同时保留原有的航班快捷路径。

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| `jeeves-tools` | 通过原有工具注册表执行，另行记录搜索线索，或请求 URL、最终 URL 与正文完整性。HTTP 重定向仍逐跳检查。 | 不通过正文、摘要或模型声称的 URL 补齐回执。 |
| `jeeves-loop::evidence` | 只审查带有完整、绑定正文回执的调用。按适配器给定的实体、记录时效、候选标识和值判定 `Confirmed`、`Conflict` 或 `Insufficient`。 | 不理解航班、商户或软件包，不把抓取时间当作记录生效时间。 |
| `jeeves-loop::run_with_evidence` | 预取可选并走常规工具准入、预算、取消与 checkpoint。硬回答约束也可单独使用，屏蔽模型草稿的流式输出与文本观察事件。 | 不替应用决定何时启用核验，也不把不确定副作用换成普通答复。 |
| `jeeves-app-server::turn::search_policy` | 选择已注册的应用策略。航班适配器负责原有入口、来源/页面规则、航班说明和无座位图时的条件式建议。 | 不把航班业务规则加到执行循环。 |

## 接入下一个场景

1. 由应用生成查询实体和时效规则。比如门店价格用「门店 + SKU + 规格」和本地日期。发布版本用「项目 + 渠道」以及明确的日期窗口。
2. 针对可接受的来源验证最终 URL，并从一个完整记录提取实体、记录日期、候选标识和值。不要跨行或跨页替记录补字段。
3. 把结构化记录交给 `resolve`。错实体、旧日期、未标日期、失败或截断读取不能支持有时效要求的断言。若一个候选满足查询条件，但另一个有效记录对同一候选给出不同值，拒绝确认。多个合格候选也判为冲突，重复读取不投票。
4. 用应用的确定性回答约束处理三个判定。确认只引用支撑记录并保留其适用范围。冲突和证据不足分别说明，不把未找到说成不存在。不要用未约束的模型草稿作为兜底。

## 首阶段边界

线上只迁移原有航班入口，没有给其他问句新增自动触发规则。运行器和证据判定不含 FlightStats 规则，现有航班来源限制和 HTTP 抓取回退保持不变。未匹配座位图时不给排号、座位号或左右侧建议，公开航班详情也不验证用户订单。

MCP 提取结果在严格核验中标为 `Unbound`，其文本仍可供普通搜索上下文使用。

## 研究引用的读取回执

`/web_research` 和 `/deep_research` 使用同一个来源记录入口。搜索阶段可使用 Parallel MCP，选中准备引用的页面后由宿主发起直接 HTTP 读取。只有回执中的请求 URL 匹配、最终 URL 可用且正文完整时，工具才会分配可引用的来源编号。重定向后的最终 URL 用于交付中的引用。查不到正文时，对应问题保持待核实。

深度研究把回执、读取时间、去除宿主提示后的页面正文和 SHA-256 存入任务状态。模型看到的长文预览有单独的长度限制。恢复时重新核对回执和正文哈希，缺回执或哈希不匹配的旧来源退出引用候选，保留原编号供历史消息对照。

这一步覆盖来源和逐字摘录。实体、日期和结论之间的关系仍由场景适配器检查。对于开放式研究，运行时交付可复核的摘录和未解决的问题。

## 门店商品报价

在两种研究命令里，一行 `price` 加 JSON 对象会开启结构化报价核验。例子使用演示域名和明确的当地日期，`url` 可省略。其他行仍可放普通研究问题。

```text
/web_research
price {"host":"shop.example","store":"南山店","sku":"A250","variant":"250ml","date":"2026-11-27","conditions":"无优惠","url":"https://shop.example/quotes"}
```

首版适配器识别商家公开 HTTPS JSON 报价源。报价源返回 `offers` 数组，每条报价包含整组字段。金额为最多两位小数的字符串，币种为 CNY，`checkout_total` 表示商家明确列出的到手总价。门店、SKU、规格、日期及优惠条件按相同口径匹配。

```json
{
  "offers": [
    {
      "store": "南山店",
      "sku": "A250",
      "variant": "250ml",
      "date": "2026-11-27",
      "conditions": "无优惠",
      "currency": "CNY",
      "priceKind": "checkout_total",
      "amount": "299.00"
    }
  ]
}
```

系统对用户指定域名中已经完整读到的报价逐条判断，并标出来源 URL、报价记录序号及读取时间。字段缺失或只列起售价时，结果保留待核实的记录与缺项。同口径读到不同金额时，结果列出冲突证据，深度研究留在待核实状态。普通网页可继续作为研究摘录，首版报价适配器需要上述结构化字段。

### 真实商家验收 · 宜家中国

2026-11-27 检查了宜家中国 RÅSKOG 白色手推车（205.867.88，35 × 45 × 77 厘米）及深圳商场。官网商品页显示网站标价。商场页说明本店活动的范围，商品页引导顾客按门店查询库存。官网使用条款也说明成交价格由结算条件决定。现有公开证据无法把这个 SKU、深圳实体店、指定日期和无优惠到手价绑定到一条记录。

- [商品页](https://www.ikea.cn/cn/zh/p/20586788/?artType=art)
- [深圳商场页](https://www.ikea.cn/cn/zh/stores/shenzhen/)
- [宜家中国使用条款](https://www.ikea.cn/cn/zh/customer-service/terms-conditions/)

基于这些页面整理的离线回放通过了快速研究和深度研究。两者均保留了已读来源并给出待核实结果，深度研究没有生成完成交付。本次执行环境中，Jeeves 的直接抓取在域名校验处失败，两条联网链路均保持待核实。公网直读验收可通过以下测试复跑，测试使用脚本化模型且只读取公开页面。

```sh
cargo test --locked -p jeeves-app-server --lib \
  live_merchant_catalog_stays_unresolved_in_both_research_modes -- --ignored --nocapture
```

正向验收需要商家公开提供包含实体店、SKU、规格、有效日期、优惠条件和固定到手总价的报价记录。宜家案例用于验证网站标价与门店活动的边界。

#### 真实模型验收

使用环境中已配置的 `DEEPSEEK_API_KEY` 运行这两项。已有 Jeeves 模型配置时，也可通过 `JEEVES_TEST_MODEL_HOME` 和 `JEEVES_TEST_MODEL_PROFILE` 指定配置目录及模型配置 ID，复用其中已保存的凭据。两项都调用 Jeeves 的真实 DeepSeek provider。网页内容固定为上述公开商品页和商场页的摘录，以便单独检查模型的阅读、工具选择和证据判断，公网直读由上一节的测试覆盖。

```sh
cargo test --locked -p jeeves-app-server --lib \
  deepseek_merchant_acceptance_with_public_page_replay -- --ignored --nocapture

cargo test --locked -p jeeves-app-server --lib \
  deepseek_natural_merchant_question_leaves_checkout_unresolved -- --ignored --nocapture
```

结构化用例覆盖快速与深度研究，另一个用例走普通自然语言研究入口。验收要求模型实际收到 API 响应、自主读取两个来源，并保持到手价待核实。深度研究同时检查完成交付状态。日志输出请求响应数量、用量和读取的公开 URL。
