# 在主聊天里交办周期委托

[English](composable-responsibilities.md) | 简体中文

用户可以在主聊天说出一项私人摘要需求，预览真实来源条目后启用。随后在原对话说出新时间、增减来源、暂停或恢复。确认卡显示选定时间、时区、投递位置和有效期。「我的事项」列出已确认的委托及每次运行记录。[Runtime 协议](../protocol.zh.md)

## 用户可以组合什么

私人摘要可以选用已连接的日历、未读邮件和 Jeeves 未完成事项。日历按约定时区读取今天、明天、本周或下周。输出可选列表或每个来源一段，并附来源记录标识。必要来源读取失败时，本次运行进入可查看的复核状态。模型提出结构化变更，Rust 校验字段，把用户确认绑定到对应版本，再按已批准的定义读取和排版。接入新来源、新判断条件、新投递渠道或需要回执的新动作，仍需工程实现。自然语言请求不能安装工具或替用户开启连接器。

通用委托在 Runtime 运行期间检查到点的分钟。已有晨报保留休眠和启动补跑规则。过期或重复的确认不能覆盖较新的版本。私人摘要与主聊天投递记录在同一事务中提交。飞书周报在外发前仍要检查连接器开关、对应审批及投递回执。[执行与审批协议](../protocol.zh.md)

## 三个旧任务如何切换

| 委托 | 时钟与保留的证据 | 用户如何操作 |
| --- | --- | --- |
| 周报 | 迁移 0008 把研究任务、收件人、触发时刻、草稿、审批标识及已有结果转入共享运行账本。发送中断的记录保留给人工核对。 | 查看已核验来源的草稿，再批准这一次飞书发送。 |
| 晨报 | 迁移 0009 引入时钟归属。启用的晨报在同一事务认领当地 08:00 的时刻并登记唤醒，调度完成记录和本次运行终态也一起提交。 | 时区及草稿箱或通知目的地沿用晨报设置。其他时间或来源组合可在聊天里建立私人摘要。 |
| 比价 | 迁移 0010 把周期委托绑定到原盯价事项，保留报价证据、运费、币种、上限版本及下次检查时间。首次命中与主聊天投递同时提交。 | 在「我的事项」选中原盯价事项，说出新的价格上限。改价前发起、改价后才返回的查询不能按旧上限提醒。 |

## 复验第四个需求

验收请求是「每周五下午把下周会议和当前未完成任务整理成两段发到这个聊天，带来源」。原句和脚本模型回复位于测试夹具中，此次组合复用了已有能力。

- 运行 `just smoke-recurring-work`。Chrome 从聊天输入框发起请求，预览两次、启用、改为周四只保留会议，再暂停。脚本分别走本地网关和带 Go 控制面的 HTTPS 网关，两组均使用一次性账号、回环日历、合成事项和可控时钟。浏览器运行记录与 SQLite 交叉核对。重复的周五信号、改期后的旧周五、暂停后的下一次周四均不增加投递。另换一种说法，可以预览按列表整理的今日日历，然后取消。
- 两组夹具的委托标识均为 `planning-digest`。版本 1 和 2 各生成一次已确认的本地投递，版本 3 为暂停。正文引用日历 UID 和开始时间，首版还引用未完成事项 ID。预览不推进时钟、不生成授权或对外回执。测试接收端单独计数通知请求。
- [真实模型对话记录](../../evals/results/recurring-work-live.json)保留了实际答复、规范化委托及模拟所有者确认。DeepSeek Flash 在卡片中选用上海时间周五 15:00，并说明这是对「下午」的假设。改期后答复仅保留一段会议，收到暂停请求后要求确认。该运行验证语义理解；浏览器夹具验证投递与重启。
- 用 `just smoke-weekly-report`、`just eval-morning-briefing`、`just smoke-price-watch` 和 `just check` 复验旧任务及仓库门禁。飞书接收端和报价源均为本地测试服务。托管路由使用回环 HTTPS 和开发租户绑定，所有验收使用隔离数据。

## 组合触发与动作

所有者可以约定具体时间、确认后的延迟、固定间隔、日历时间或某个已签名连接器的事件。例如，连接器提供发件人和附件媒体类型后，两个条件都满足时才在私人聊天里提醒。筛选条件和输出字段随定义确认。同一个记录动作可以换用其他连接器、字段或条件值。事件预览使用账户可用的最近一笔样例，不推进来源游标，也不投递。

动作注册项定义参数、审阅字段和执行效果。确定性动作在运行时不调用模型。限额模型草稿可引用审阅时保存的技能版本。Runtime 每次检查来源和连接器权限，按确认版本固定技能正文，并对模型请求记账。飞书投递继续逐次审批具体草稿，并读取回执。

定时和事件入口执行前都登记唯一唤醒。通用定时任务恢复后只执行 15 分钟窗口内最新一次。签名来源在登记唤醒的同一事务中推进游标，重复事件返回确认但不再次执行。租约失效或派发中断会留待复核。晨报和比价沿用兼容时钟与原有回执，改由公共执行器准备结果。托管测试在回环环境验证账号到 Runtime 的路由及签名事件入口。

- 用 `just smoke-recurring-work --case event` 复验报销邮件。发件人不符和附件类型不符的事件会跳过；命中后仅一条带原邮件引用的主聊天投递。重启前后重复发送同一个事件、暂停后发送新事件都不会增加投递。夹具还核对事件执行期间模型请求数和外发数都为零。
- [真实模型验收](../../evals/results/recurring-event-live.json)记录了模型选择已配置的来源、使用 PDF 的 MIME 值并生成待审卡。来源数据为合成邮件元数据。
- 签名事件适配器的运维配置见[入站 Webhook](../configuration.zh.md)。
