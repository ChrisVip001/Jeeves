# Jeeves 设计：对话、事项与交付

[English](main-entry.md) | 简体中文

本文是 Jeeves 唯一的最终设计稿。它定义产品模型、运行时契约与验收证据、周期委托，以及视觉与语气规范所在的位置。具体实现细节留在链接的运行时代码与协议中。

## 1. 从一句话开始

像平常说话一样和 Jeeves 沟通。它可以直接回答问题，也可以接手一件事，从很快就能做完的比较到需要多天的复杂工作。还没想好怎么交代时，可以先说情况。

Web 和 iOS 工作区共用一个 Runtime 主对话。飞书保留发送者和聊天来源，只能接续该来源派发的事项。任务有需要时，配对的 Mac 可授权访问所选窗口。主界面保留对话与「工作」，账号、设备和连接管理在菜单内。聊天记录先展示人的请求和助理的答复，时间旁可以展开执行细节。

云工作区启动期间可以先写下要交办的事。刷新当前页面仍保留草稿，主对话就绪后即可发送。

输入区显示工作目录和当前续办事项。需要授权时，对话内显示本次操作和预览，由用户决定。模型路由、运行限额和权限策略通过 Runtime 的管理接口配置。首次单机配置见[上手指南](../guide.zh.md)。

## 2. 请求、目标、交付

Jeeves 把「用户交代的事」和「这件事怎么执行」分开：

| 层次 | 是什么 | 用户是否看到 |
|---|---|---|
| **请求** | 用户用自己的话说的任何内容——一个问题、一个模糊的念头、一张图加几句话，或一份详细的交办 | 就是用户自己说的话，留在对话里 |
| **目标** | Jeeves 从请求里提炼出的结果；必要时先澄清成明确的目标 | 动手前在对话里确认 |
| **交付** | 完成后的结果：有出处的结论、比价清单、文件、验证过的程序，或授权操作的回执 | 在对话里呈现 |

用哪种方式达成目标是 Jeeves 的内部调度决定，不需要用户懂这个概念。简单问答当场完成；需要多步、查外部来源或要授权的工作，也可以在对话内一路做完。只有必须跨重启继续、有自己的工作目录、或要按既定标准核验的工作，才成为**任务线程**——一份带预算、检查点和返回位置的持久记录。任务线程只是达成目标的一种方式，不是目标本身的另一种说法。每个线程都从最近的结果、待定决定和交付文件打开，需要人判断时回到交办者。

Jeeves 从对话里提炼要达成的结果，把用户已有的约束带进目标。能先查清的就先查，能用可逆假设推进的就先做。只有缺失的信息会实质改变结果、成本或授权，并且无法从已有信息判断时，才问一个具体的问题。当场回答、在对话内执行、还是开任务线程，是由目标性质决定的调度，不是用户要按的按钮。交付随事情而定：有出处的结论、文件、新建或改好的程序及验证结果，或已获授权操作的回执。对外操作做到哪一步，以服务响应或可核对的记录为准。

| 用户想做什么 | 交互 |
|---|---|
| 交办 | 在主对话里说明想办的事，可以附文件。任务标题概括目标，任务保留原始请求。已绑定的项目目录显示在输入框上方。Jeeves 开始的每件事会在回复下显示成一张带实时状态的卡片，点它进入「工作」里的这件事，刷新后卡片仍在。新事项使用干净 Git 仓库时会创建独立工作树。点目录即可切回自动工作区。 |
| 接手决定 | 一条待确认请求自动展示动作与预览。按当前请求允许一次或拒绝。 |
| 中断恢复 | 在原事项页核对操作，再点「继续任务」。[操作核对流程](../operations.zh.md#核对未知操作) |
| 找回一件事 | 在「工作」搜索标题，或者从对话回执进入。宽屏上列表留在左栏，打开的事项占右栏；手机上从列表点进详情页。刷新、浏览器返回和前进均保留导航位置。 |
| 阅读交付 | 最近一次结束的执行有独立回执。页面把结果和文件放在前面，往来记录按需展开。旧 Runtime 的最近回复单独标明。 |
| 查看文件 | 点交付文件，在 Mac 右侧或手机全屏查看预览。仓库任务可以切换到「逐行差异」，用原行号和新行号检查新增与删除。普通文本可在面板保存副本。 |
| 继续修改 | 在事项内直接补充。主对话和不同事项的草稿各自保存在当前浏览器标签页。再次进入相同事项可以继续编辑。 |
| 管理账户 | 个人中心首先显示账号和助理入口；展开「账号与安全」可管理登录设备、密码和双因素认证。 |

### 主聊天模型与任务指代

主聊天首选评测候选为 DeepSeek V4.1 Flash，官方模型 ID 为 `deepseek-flash`。此次选择仅用于主聊天意图评测。后台任务沿用其执行模型，开发使用 GPT-6.2 Sol / high，默认配置保持现状。在仓库根目录运行 `cargo run -p jeeves-provider --example deepseek_intents -- <Jeeves目录> <Flash配置名>` 可手动复验意图识别。

用户说「刚才那个先别发，改成草稿」时，Runtime 按用户所选任务或明确引用解析改稿请求。回指可使用紧邻的上一条已完成私聊交互。存在多个候选发送动作时，由用户选择动作 ID。任务使用 iPhone 与 Mac 共享的固定 ID，发送动作有独立记录。同一会话中有两个合理目标时，主聊天用可区分的邮件主题或任务名称请用户选择；单凭最近更新时间不足以选定目标。澄清前保留原状。

Runtime 核对任务归属、发送动作与任务的关联、当前动作状态及权限，只对唯一且仍有效的目标应用变更。任务进度不能证明邮件已发出或已撤销。是否还能拦下发送，取决于改稿事务和发送器领取哪个先提交；给用户的答复以持久化动作记录和接收回执为准。详见[任务邮件约定](../configuration.zh.md#日历与邮件)。

用已配置的只读报价来源比完价后，可以请 Jeeves 盯住其中一个规格几天。事项保留原来源、规格和币种，每小时核对一次含运费的到手价。在手机的「工作」打开同一事项即可改阈值。第一次核实到手价严格低于当前阈值时，Jeeves 把价格和出处发回原对话。价格相等、运费未知或到期都不会触发提醒。盯价只授权查询价格。

「等你决定」是 Jeeves 优先级最高的通知。用户在 iPhone 主聊天中作答，答复转交正在等待的原任务。任务转为「已完成」时，Jeeves 以普通优先级主动通知一次，并在最初交办的主聊天中汇报结果。日常进度只在约定的里程碑汇报，其余时候静默更新。系统通知始终遵循用户的 iOS 通知设置。

## 3. 各类用途放在哪里

| 用途 | 位置 | 说明 |
|---|---|---|
| 聊天 | 主线 | 普通回答 |
| 搜资料 | 简单的在主线直接答；需要调研一阵的开成任务 | 结论回到主线 |
| 内网与本地检索 | 主线或任务线程，检索已接入的内网来源与本地文件 | 来自内网和本地文档、带来源的结论 |
| 文档交付（幻灯片、表格、Markdown） | 任务线程，带素材 | 可直接打开、审阅和修改的交付文件 |
| 写代码 | 任务线程，带工作区 | diff、测试结果；合并前汇报并等确认 |
| 跑复杂长任务 | 任务线程 | 开始时说明思路，在预计节点汇报进展，有交付风险时尽早说明 |
| 监控时间、价格 | 常驻任务（定时或事件触发） | 触发时才在主线说话；提醒就是 `trigger = once` 的任务 |
| 比价 | 主聊天或任务线程 | 提供可选商品、当前价格、库存和来源 |
| 下单 | 已配置可用购物渠道的任务线程 | 下单前确认商品、总价和付款方式。下单成功后交付订单回执。 |
| 做视频、创作 | 任务线程，带素材和成片预览 | 选题和发布前由用户拍板 |

主对话交办、直接创建和重启续办的事项共用验收条件。Runtime 可以检查文件及指定原文、JSON 字段值、引文与来源快照、用户指定测试的退出码，以及操作记录和回执。验收命令沿用当前工作区的执行权限。某项失败后，Jeeves 在原事项的轮数限额内补做；详情保留每轮的条件和实测结果。交付后继续追问，会在同一任务和工作区开启新一次执行，上一次的检查不沿用。如果追问本身点明了文件、必须包含的原文或测试命令，这些就成为新一次执行的验收条件，没通过就在原事项里补做；否则产出标为未验证。事项执行时用了工具，却既没有验收条件也没有 `/goal` 条件，交付前会在轮数限额内多做一轮自查：Jeeves 重读原始交办，打开自己的产出，补上缺漏，并说明哪些没法核实。任务时间线会记下这一轮。自查不是实测，所以结果仍标为未验证。补做没有进展时会提前停下：从第一轮补做之后算起，某一轮结束时的未通过检查或目标判定和上一轮相同，或者这一轮没有成功调用任何工具，就算原地踏步。连续两轮原地踏步，事项转为需要你处理，并附上反复出现的原因，不再耗完剩下的轮数。

### 长任务如何协作

接到长任务时，Jeeves 简要说明打算怎么做、预计在哪些节点汇报。如果某项决定会实质改变已约定的目标、成本、权限或承诺，先请用户决定。一旦发现承诺的结果可能无法交付，就尽早说明哪里有风险、还能交付什么。资源额度用尽、用户主动暂停，或外部操作的结果需要核对时，任务会停下来。[Runtime 限额](../configuration.zh.md#行为旋钮)

Mac 和手机可以搜索任务标题并打开同一执行会话，主聊天汇集任务通知和回执。

## 4. 运行时契约

主对话可以当场交付结果，也可以在同一目标上继续成持久任务。本节记录实现契约，验收证据见第 5 节。

**对话与任务归属。** 私聊主对话根据请求决定当场交付还是委派。每次操作的准入取决于用户、来源、工作区、设备授权和动作。早先的外部效果尚未结算时，保持对后续变更的限制。同一个 Rust 驱动服务对话工作、持久工作和恢复。app-server 拥有准入与调度，外壳只提交人的请求并渲染已提交的结果。[工具装配](../../runtime/crates/jeeves-app-server/src/turn/execution.rs) · [架构](../architecture.zh.md)

**工作转入任务。** 在一次可恢复的转换里绑定原始消息、确认的目标、当前补充、证据引用、已结算动作、剩余工作和返回位置。即使进程在创建和派发之间停止，重试请求也必须恢复同一个任务。旧的实测值跟着它校验的版本走；新阈值取代旧阈值。复用持久交接与来源所有权检查。任务在转换中保留原有的权限边界。[主对话交接](../../runtime/crates/jeeves-app-server/src/interaction/task_tool.rs) · [任务交接](../../runtime/crates/jeeves-app-server/src/task/handoff.rs)

**工具调用与恢复。** 每个拟议调用都有稳定身份。把有外部效果的调用交给执行器之前，先持久化派发意图；在推进到依赖动作之前，先提交观察到的结果。派发意图与确认结果之间崩溃，会让该调用处于不确定状态。保留「从未准入」与「已提交结果」的证据。独立读取可以各自完成与上报，其对模型的结果仍保持请求顺序。工具边界返回带类型的执行状态、可读输出与证据引用。任务步骤、通知和验收输入都从这些记录派生；不从文本前缀推断状态，不从模型记录重建已执行的调用。[循环](../../runtime/crates/jeeves-loop/src/lib.rs) · [操作记录](../../runtime/crates/jeeves-state/src/operations.rs) · [任务观测](../../runtime/crates/jeeves-agent/src/observe.rs)

**模型请求与上下文。** 记录每个请求的目的、执行归属、终止状态和服务商上报的用量。在适配层规范化完整输入、输出和缓存明细。一次请求把完整输入加输出计入任务一次，包括它调用的规划、摘要或评判。上下文占用、任务累计消耗和费用分开保存。失败请求上的未知用量也要保留。续跑和恢复都用当前指令、补充、已结算结果、待定决定和可寻址证据组装上下文。压缩时保留文件、来源和回执引用。对照这份基线评估模型生成摘要的收益与成本。[用量](../../runtime/crates/jeeves-provider/src/lib.rs) · [预算](../../runtime/crates/jeeves-loop/src/budget.rs) · [投影](../../runtime/crates/jeeves-loop/src/projection.rs)

**交付与验收。** 主对话交办、显式任务和续跑共用同一套带类型条件。调研返回带出处的结论，文档返回可打开的产物，代码返回测试过的版本和实测结果，授权发送返回服务回执。主观复核与机械检查分开记录。验收命令按正常执行策略运行。失败条件驱动同一任务内补做，并与后来的实测结果一起保留。[验收器](../../runtime/crates/jeeves-agent/src/verify.rs) · [交付回归](../../runtime/crates/jeeves-app-server/src/interaction/tests/deliverables.rs)

## 5. 验收证据

四个阶段把设计落进产品。每行给出退出条件和本地证据。确定性回归、真实模型试验和部署检查分别记录，不能互相替代。

| 阶段 | 退出条件 | 证据 |
|---|---|---|
| 1 · 在对话内交付 | 截图提问、带出处的比价、预览后的一次性审批都在输入区完成，不创建任务。拒绝不改接收方；工具成功但返回以 `Error:` 开头的文本也记为成功。 | 2026-11-23 通过。`just smoke-interaction --browser chrome`；八项 `just smoke-recovery` 全通过。 |

| 3 · 恢复、计费、验收 | 在派发前、派发后、结算后打断。回执丢失时重开已存报告，只核对发送。两种服务商用量格式在重启后停在同一预算边界。压缩与补充后，后续请求仍带新约束和早期来源。错误 JSON、无出处引文、失败的测试各让交付保持待补做。 | 2026-11-23 通过 `just smoke-runtime-contract`。 |
| 4 · 切换客户端并迁移存储 | 在现有 Mac 数据副本上迁移，再在自托管与隔离托管 Runtime 上重复交办、审批与交付。Web 和 iOS 共用对话；飞书保留来源；Mac 只在授权内操作所选窗口。 | 2026-11-23 通过。`just check`、`just smoke-account`、`just smoke-interaction --browser chrome`、`just smoke-price-watch --ios-simulator <UDID>`、`just smoke-mac-window`。 |

真实模型试验统计可避免的追问、多余的任务、丢失的补充、无依据的结论和独立核验的交付；接收方测试统计实际外部效果。分别记录模型、耗时和用量，区分模拟时间、真实跨夜运行和物理设备观察。

## 6. 周期委托

描述时间或事件、想要的结果和接收位置。Jeeves 提交一张卡片给所有者审阅。之后的请求可以修改、暂停或恢复同一项委托。「工作」显示确认过的定义和运行记录。新账户没有预置周期委托。

**组合。** 触发方式可以是具体时间、确认后延迟、固定间隔、日历计划或签名来源事件。确定性动作可以生成提醒、用固定参数从已批准来源汇总摘要、核验已保存证据或检查结构化记录。读取动作调用一个已启用的只读工具，把结构化结果作为文本返回。摘要可列出多个来源，每个来源都是已批准的只读工具加固定参数，或兼容早期的 calendar/task/mail 命名来源。记录动作可检查收到的事件、有效期内的最近签名记录，或每次运行时从已批准的只读工具取数后判定。审阅卡上显示确切的工具、参数、比较条件、单位或字段，以及接收位置。`capabilities` 结果列出所有可用只读工具及其输入 schema。

模型草稿可以引用已审阅的已安装技能版本。来源与连接器能力由所有者单独启用。用已启用能力组合新委托，无需改动引擎。新的服务商认证流程、来源协议或外部写操作需要实现连接器。

**交付。** 本地交付出现在主聊天或保留为私密草稿。出站连接器适配器通过同一份能力目录公开目的地，复用现有审批与回执边界。飞书集成只在所有者启用后运行。每次外发都须审批确切内容和收件人，并在发出前再次核对当前版本和连接器权限范围。

**执行与恢复。** 定时与签名事件准入为每个 occurrence 记录一条唤醒。定时在 15 分钟追赶窗口内最多认领一次最近的 occurrence。签名事件在一个事务里推进游标并创建唤醒。重复的事件或时间槽不再投递。版本变化会扣住未结算的唤醒等待审阅。执行租约过期或中断会留下待审阅记录。运行历史显示被阻断、跳过、已投递和中断的 occurrence。预览只做只读检查，不推进时钟或事件游标。[运行时协议](../protocol.zh.md)

**升级后的委托。** 每周研究报告保留已验证证据动作、七日窗口和授权 URL，保存的收件人变为连接器目的地。配置的晨报暂停为待确认的私密摘要，直到所有者确认来源、时间和接收位置。比价监控暂停，观测、历史、阈值修订和回执保留；恢复需要重新确认结构化规则。

**验收。** `just smoke-recurring-work` 创建、预览、修改并暂停摘要，并跑一条零模型请求的签名来源事件用例。`just eval-morning-briefing` 与 `just smoke-price-watch` 升级 v14 数据库并检查重启后的暂停委托。`just smoke-weekly-report` 覆盖旧登记入口、审批、回环飞书接收器和崩溃核对。[真实模型费用邮件验收](../../evals/results/recurring-event-live.json)记录了自然语言提议与合成邮件元数据。

## 7. 呈现与语气

[视觉设计系统](DESIGN.md)负责颜色 token、字体、间距、组件和布局。[语气与汇报规范](voice.zh.md)负责每一句文案的写法、汇报卡结构和基线人格。两者面向的读者不同于本设计，因此不在此重复。改动任务栏、卡片或确认交互前，先读这两份手册再动组件或提示词。

任务的归属、路由和实时审批见[主交互入口协议](../protocol.zh.md#主交互入口)。
