# Jeeves 的对话与动态

[English](main-entry.md) | 简体中文

## 1. 两个入口

打开 Jeeves 就能说事。「对话」用来提问、交办和改变要求；「动态」用来找回交办过的事，分为等你决定、进行中和已结束。普通交谈直接回答，持续工作由 Jeeves 建立任务。交办成功后，用户可以马上聊下一件事。

## 2. 设计依据

Grok 可以从聊天创建定时工作，事后打开某一次执行的对话接着说。Jeeves 据此让用户从回执直接找回所对应的任务。[Grok 的自动化任务](https://x.ai/news/grok-automations)

Grok Bot 把收件人和待发正文放在谈话中供用户核对，也允许发一条新消息调整正在做的事。Jeeves 因此把需要决定的动作和可审阅的预览放回对话。[Grok Bot 的会话与协作](https://docs.x.ai/grok-bot/chat-and-collaboration)

dot 允许直接描述目标，后台继续工作，定时工作的更新进入谈话，每件任务也有自己的上下文。Jeeves 将日常交谈与查找多件工作的需要分别放在「对话」和「动态」。[OpenAI 的 dot 使用说明](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)

## 3. 从交办到交付

| 用户想做什么 | 交互 |
|---|---|
| 交办 | 在对话中写「把周一客户会的未决问题整理成一页」。附件在输入框旁，模型、工作目录与权限可在对话选项中调整。 |
| 临时改主意 | 直接补充要求。指代有歧义时，助理询问是哪一件。也可以从回执点「继续这件事」，输入框会显示所选任务的名字。 |
| 做决定 | 展开对话中的「待确认」，阅读这一次操作的预览，选择允许一次或拒绝。已记录的历史请求可展开查看。 |
| 回来看结果 | 回执显示该次执行的验收结果。需要查其他工作时打开「动态」；Mac 上点一项可进入独立对话，手机上点一项可查看内容并回到主聊天跟进。 |
| 管理助理 | 展开菜单可进入设置、连接、定时任务和其他工具。签名推送仍打开对应审批请求。 |

### 主聊天模型与任务指代

主聊天首选评测候选为 DeepSeek V4.1 Flash，官方模型 ID 为 `deepseek-flash`。此次选择仅用于主聊天意图评测。后台任务沿用其执行模型，开发使用 GPT-6.2 Sol / high，默认配置保持现状。[DeepSeek 官方模型列表](https://api-docs.deepseek.com/api/list-models/)

在 `jeeves-rs/` 中运行 `cargo run -p jeeves-provider --example deepseek_intents -- <Jeeves目录> <Flash配置名>` 可手动复验意图识别。它向官方端点发一次请求，包含普通聊天、明确交办、明确引用任务、指代不清四条合成消息，检查模型提出的意图与目标。桌面端验收另用本机夹具验证路由、审批和回执。

用户说「刚才那个先别发，改成草稿」时，Runtime 按用户所选任务或明确引用解析改稿请求。回指可使用紧邻的上一条已完成私聊交互。存在多个候选发送动作时，由用户选择动作 ID。任务使用 iPhone 与 Mac 共享的固定 ID，发送动作有独立记录。同一会话中有两个合理目标时，主聊天用可区分的邮件主题或任务名称请用户选择；单凭最近更新时间不足以选定目标。澄清前保留原状。

Runtime 核对任务归属、发送动作与任务的关联、当前动作状态及权限，只对唯一且仍有效的目标应用变更。任务进度不能证明邮件已发出或已撤销。是否还能拦下发送，取决于改稿事务和发送器领取哪个先提交；给用户的答复以持久化动作记录和接收回执为准。详见[任务邮件约定](../configuration.zh.md#日历与邮件)。

### 任务通知

「等你决定」是 Jeeves 优先级最高的通知。用户在 iPhone 主聊天中作答，答复转交正在等待的原任务。任务转为「已完成」时，Jeeves 以普通优先级主动通知一次，并在最初交办的主聊天中汇报结果。日常进度只在约定的里程碑汇报，其余时候静默更新。这些优先级用于 Jeeves 内的提醒。系统通知始终遵循用户的 iOS 通知设置。

## 4. 各类用途放在哪里

| 用途 | 位置 | 说明 |
|---|---|---|
| 聊天、八卦、倾诉 | 主线 | 不用汇报格式 |
| 搜资料 | 简单的在主线直接答；需要调研一阵的开成任务 | 结论回到主线 |
| 写代码 | 任务线程，带工作区 | diff、测试结果；合并前汇报并等确认 |
| 跑复杂长任务 | 任务线程 | 开始时说明思路，在预计节点汇报进展，有交付风险时尽早说明 |
| 监控时间、价格 | 常驻任务（定时或事件触发） | 触发时才在主线说话；提醒就是 `trigger = once` 的任务 |
| 比价并下单 | 任务线程 | 比价自主完成；**下单前发确认卡片**：商品、总价、付款方式 |
| 做视频、创作 | 任务线程，带素材和成片预览 | 选题和发布前由用户拍板 |

### 长任务如何协作

用户明确指定输出文件时，主聊天可以把文件检查随任务交办。如果用户还写明必须包含的原文，就到文件中查验这段文字。Runtime 在任务工作区核验并记录结果，验收失败会在轮数上限内交回同一任务补做。任务详情中可以查看验收条件和结果。来源准确性、代码行为等要求还需要相应的证据。

交付后继续追问，会在同一任务和工作区开启新一次执行。上次的验收回执保留在原执行记录中。追问当前以空验收条件开始，产出会标为未验证。

接到长任务时，Jeeves 简要说明打算怎么做、预计在哪些节点汇报。执行中，常规步骤可以随情况自行调整。如果某项决定会实质改变已约定的目标、成本、权限或承诺，先请用户决定。一旦发现承诺的结果可能无法交付，就尽早说明哪里有风险、还能交付什么。

## 5. 对现有实现的影响

手机任务列表和 Mac Cowork 可查看同一执行会话。主聊天汇集任务通知和回执。按天浏览和搜索历史任务仍在规划中。
