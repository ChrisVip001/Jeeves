# Jeeves 的对话、事项与交付

[English](main-entry.md) | 简体中文

## 1. 从一句话开始

像平常说话一样和 Jeeves 沟通。它可以直接回答问题，也可以接手一件事，从很快就能做完的比较到需要多天的复杂工作。还没想好怎么交代时，可以先说情况。

Web 和 iOS 工作区共用一个 Runtime 主对话。飞书保留发送者和聊天来源，只能接续该来源派发的事项。任务有需要时，配对的 Mac 可授权访问所选窗口。主界面保留对话与「我的事项」，账户、工具和运行设置在菜单内。聊天记录先展示人的请求和助理的答复，时间旁可以展开执行细节。

云工作区启动期间可以先写下要交办的事。刷新当前页面仍保留草稿，主对话就绪后即可发送。

### 界面边界

目标形态是克制的工作台：目标栏在最上，对话是人说明结果、做决定、收交付的地方。模型、权限、定时、用量和审计等配置属于 CLI、`models.json`、`model-routes.json` 和 `/api/*`，不放在驾驶舱面板里；审批卡留在对话窗口内。当前版本仍保留设置、模型/权限选择器和能力中心，作为通往该边界的过渡实现——它们是过渡态，不是应继续扩展的目标。

## 2. 设计依据

Grok 允许打开一次自动化运行的完整对话继续工作。dot 允许从对话交办，后台工作持续推进，需要人判断时再回来。Jeeves 因此为每件工作保留可返回的位置，首先展示最近的结果、需要的决定和能带走的文件。[Grok 自动化](https://x.ai/news/grok-automations) · [dot 使用说明](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)

## 3. 从交办到交付

Jeeves 从对话里提炼要达成的结果，把用户已有的约束带进任务。能先查清的就先查，能用可逆假设推进的就先做。只有缺失的信息会实质改变结果、成本或授权，并且无法从已有信息判断时，才问一个具体的问题。

交付随事情而定。可以是有出处的结论、文件、新建或改好的程序及验证结果，也可以是已获授权操作的回执。对外操作做到哪一步，以服务响应或可核对的记录为准。

| 用户想做什么 | 交互 |
|---|---|
| 交办 | 在主对话里说明想办的事，可以附文件。任务标题概括目标，任务保留原始请求。已绑定的项目目录显示在输入框上方。新事项使用干净 Git 仓库时会创建独立工作树。点目录即可切回自动工作区。 |
| 接手决定 | 一条待确认请求自动展示动作与预览。按当前请求允许一次或拒绝。 |
| 中断恢复 | 在原事项页核对操作，再点「继续任务」。[操作核对流程](../operations.zh.md#核对未知操作) |
| 找回一件事 | 在「我的事项」搜索标题，或者从对话回执进入。Mac 和手机打开同一个事项页面。刷新、浏览器返回和前进均保留导航位置。 |
| 阅读交付 | 最近一次结束的执行有独立回执。页面把结果和文件放在前面，往来记录按需展开。旧 Runtime 的最近回复单独标明。 |
| 查看文件 | 点交付文件，在 Mac 右侧或手机全屏查看预览。仓库任务可以切换到「逐行差异」，用原行号和新行号检查新增与删除。普通文本可在面板保存副本。 |
| 继续修改 | 在事项内直接补充。主对话和不同事项的草稿各自保存在当前浏览器标签页。再次进入相同事项可以继续编辑。 |
| 管理账户 | 个人中心首先显示账号和助理入口；展开「账号与安全」可管理登录设备、密码和双因素认证。 |

### 主聊天模型与任务指代

主聊天首选评测候选为 DeepSeek V4.1 Flash，官方模型 ID 为 `deepseek-flash`。此次选择仅用于主聊天意图评测。后台任务沿用其执行模型，开发使用 GPT-6.2 Sol / high，默认配置保持现状。[DeepSeek 官方模型列表](https://api-docs.deepseek.com/api/list-models/)

在仓库根目录运行 `cargo run -p jeeves-provider --example deepseek_intents -- <Jeeves目录> <Flash配置名>` 可手动复验意图识别。它向官方端点发一次请求，包含普通聊天、明确交办、明确引用任务、指代不清四条合成消息，检查模型提出的意图与目标。桌面端验收另用本机夹具验证路由、审批和回执。

用户说「刚才那个先别发，改成草稿」时，Runtime 按用户所选任务或明确引用解析改稿请求。回指可使用紧邻的上一条已完成私聊交互。存在多个候选发送动作时，由用户选择动作 ID。任务使用 iPhone 与 Mac 共享的固定 ID，发送动作有独立记录。同一会话中有两个合理目标时，主聊天用可区分的邮件主题或任务名称请用户选择；单凭最近更新时间不足以选定目标。澄清前保留原状。

Runtime 核对任务归属、发送动作与任务的关联、当前动作状态及权限，只对唯一且仍有效的目标应用变更。任务进度不能证明邮件已发出或已撤销。是否还能拦下发送，取决于改稿事务和发送器领取哪个先提交；给用户的答复以持久化动作记录和接收回执为准。详见[任务邮件约定](../configuration.zh.md#日历与邮件)。

### 任务通知

「等你决定」是 Jeeves 优先级最高的通知。用户在 iPhone 主聊天中作答，答复转交正在等待的原任务。任务转为「已完成」时，Jeeves 以普通优先级主动通知一次，并在最初交办的主聊天中汇报结果。日常进度只在约定的里程碑汇报，其余时候静默更新。这些优先级用于 Jeeves 内的提醒。系统通知始终遵循用户的 iOS 通知设置。

## 4. 各类用途放在哪里

| 用途 | 位置 | 说明 |
|---|---|---|
| 聊天、八卦、倾诉 | 主线 | 不用汇报格式 |
| 搜资料 | 简单的在主线直接答；需要调研一阵的开成任务 | 结论回到主线 |
| 内网与本地检索 | 主线或任务线程，检索已接入的内网来源与本地文件 | 来自内网和本地文档、带来源的结论 |
| 文档交付（幻灯片、表格、Markdown） | 任务线程，带素材 | 可直接打开、审阅和修改的交付文件 |
| 写代码 | 任务线程，带工作区 | diff、测试结果；合并前汇报并等确认 |
| 跑复杂长任务 | 任务线程 | 开始时说明思路，在预计节点汇报进展，有交付风险时尽早说明 |
| 监控时间、价格 | 常驻任务（定时或事件触发） | 触发时才在主线说话；提醒就是 `trigger = once` 的任务 |
| 比价 | 主聊天或任务线程 | 提供可选商品、当前价格、库存和来源 |
| 下单 | 已配置可用购物渠道的任务线程 | 下单前确认商品、总价和付款方式。下单成功后交付订单回执。 |
| 做视频、创作 | 任务线程，带素材和成片预览 | 选题和发布前由用户拍板 |

### 长任务如何协作

用户明确指定输出文件时，主聊天可以把文件检查随任务交办。如果用户还写明必须包含的原文，就到文件中查验这段文字。Runtime 在任务工作区核验并记录结果，验收失败会在轮数上限内交回同一任务补做。任务详情中可以查看验收条件和结果。来源准确性、代码行为等要求还需要相应的证据。

任务所需的工具出现问题时，Jeeves 会说明受影响的操作和当前事项里的实测结果。

交付后继续追问，会在同一任务和工作区开启新一次执行。上次的验收回执保留在原执行记录中。追问当前以空验收条件开始，产出会标为未验证。

接到长任务时，Jeeves 简要说明打算怎么做、预计在哪些节点汇报。执行中，常规步骤可以随情况自行调整。如果某项决定会实质改变已约定的目标、成本、权限或承诺，先请用户决定。一旦发现承诺的结果可能无法交付，就尽早说明哪里有风险、还能交付什么。

## 5. 对现有实现的影响

Mac 和手机可以搜索任务标题并打开同一执行会话，主聊天汇集任务通知和回执。
