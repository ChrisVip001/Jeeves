# 主入口：一条主线，多条任务线程

[English](main-entry.md) | 简体中文

主聊天与独立任务会话已由 Runtime 提供。iPhone 任务列表与 Mac 模式切换使用同一驾驶舱前端。

手机任务列表和 Mac Cowork 读取同一执行会话及产物。主聊天保留完整的发布审批预览，包括账号、渠道、目标和最终全文。按消息中的格式回复 `批准 <requestId> v<version>` 或 `拒绝 <requestId> v<version>`。向任务提交修改会使当前待答的发送审批失效。每次执行的完成回执在原主聊天中生成一条结果。

## 1. 定位

Jeeves 是通用 agent：聊天、八卦、搜资料、写代码、跑复杂长任务、监控时间和价格、比价下单、做视频和创作。用户只面对一个入口，不用先想"该在哪个会话里说"。

**入口只有一个，线程可以有很多，而且线程由 Jeeves 来开，不由用户来开。**

## 2. 为什么不是"只有一条永远往下滚的对话"

1. 找不回旧内容：三个月的聊天记录里翻不到"上周那款相机"。
2. 协作会淹没主线：写代码、改视频脚本要来回几十轮，汇报和确认卡片会被冲走。
3. 几件事混在一起："那个"指什么，用户和模型都会搞混。
4. 模型的有效上下文有限：单线程最终靠压缩和记忆撑着，越往后越容易接错话。

## 3. 结构

iPhone 上，交办新任务、补充要求、回答任务提出的问题，都在唯一的主聊天中进行。Jeeves 将补充和答复转交对应的已有任务。任务进展、待确认事项和结果也回到主聊天。

从主聊天可以查看全部任务会话，分为「进行中」「等你决定」「已完成」三组。列表和详情都只读，输入框只在主聊天。已签名推送可单独打开同一请求、同一版本的审批页；用户可在此决定一次，或回主聊天跟进刚核验的任务。点开任务，就能查看 Mac Cowork 中用户可见的同一份完整对话、详情和已有结果。

Mac 左上角可以手动切换「助理」与「Cowork」。「助理」显示同一个主聊天、相关信息和近期活动；「Cowork」是工作台，每项任务都有独立会话。它和 iPhone 列表打开的是同一条持久化任务记录和同一段对话。派发任务后保持用户所在的界面。

| 部分 | 内容 |
|---|---|
| **主线**（`jeeves-main`） | 闲聊、倾诉、随口问的问题、派任务、收汇报、确认。就是用户说的"主入口" |
| **任务线程** | 每个任务有自己的对话和上下文。在 Mac 的 Cowork 中可以打开任务并继续交流 |
| **历史** | 按天查看时间线，也能搜索已归档的任务 |

主模型识别到明确交办时，通过 `task` 创建任务会话。普通聊天、讨论和进度询问直接在主线回答。用户补充已有委托时续办原任务；指代不清时先问清是哪件事。任务的进展、待确认事项和结果回到主聊天。任务在既有权限下执行。需要对外操作时，仍按该操作的范围单独取得授权。

### 主聊天模型与任务指代

主聊天首选评测候选为 DeepSeek V4.1 Flash，官方模型 ID 为 `deepseek-flash`。此次选择仅用于主聊天意图评测。后台任务沿用其执行模型，开发使用 GPT-6.2 Sol / high，默认配置保持现状。[DeepSeek 官方模型列表](https://api-docs.deepseek.com/api/list-models/)

在 `jeeves-rs/` 中运行 `cargo run -p jeeves-provider --example deepseek_intents -- <Jeeves目录> <Flash配置名>` 可手动复验意图识别。它向官方端点发一次请求，包含普通聊天、明确交办、明确引用任务、指代不清四条合成消息，检查模型提出的意图与目标。桌面端验收另用本机夹具验证路由、审批和回执。

用户说「刚才那个先别发，改成草稿」时，Runtime 按用户所选任务或明确引用解析改稿请求。回指可使用紧邻的上一条已完成私聊交互。存在多个候选发送动作时，由用户选择动作 ID。任务使用 iPhone 与 Mac 共享的固定 ID，发送动作有独立记录。同一会话中有两个合理目标时，主聊天用可区分的邮件主题或任务名称请用户选择；单凭最近更新时间不足以选定目标。澄清前保留原状。

Runtime 核对任务归属、发送动作与任务的关联、当前动作状态及权限，只对唯一且仍有效的目标应用变更。任务进度不能证明邮件已发出或已撤销。是否还能拦下发送，取决于改稿事务和发送器领取哪个先提交；给用户的答复以持久化动作记录和接收回执为准。详见[首个架构验收场景](../planning/execution-plan.zh.md#首个架构验收场景将待发邮件改为草稿待执行)。

### 任务通知

「等你决定」是 Jeeves 优先级最高的通知。用户在 iPhone 主聊天中作答，答复转交正在等待的原任务。任务转为「已完成」时，Jeeves 以普通优先级主动通知一次，并在最初交办的主聊天中汇报结果。日常进度只在约定的里程碑汇报，其余时候静默更新。这些优先级用于 Jeeves 内的提醒。系统通知始终遵循用户的 iOS 通知设置。

## 4. 各类用途放在哪里

| 用途 | 位置 | 说明 |
|---|---|---|
| 聊天、八卦、倾诉 | 主线 | 不用汇报格式 |
| 搜资料 | 简单的在主线直接答；需要调研一阵的开成任务 | 结论回到主线 |
| 写代码 | 任务线程，带工作区 | diff、测试结果；合并前汇报并等确认 |
| 跑复杂长任务 | 任务线程 | 开始时说明思路，在预计节点汇报进展，有交付风险时尽早说明 |
| 监控时间、价格 | 常驻任务（定时或事件触发） | 触发时才在主线说话；提醒就是 `trigger = once` 的任务 |
| 比价并下单 | 任务线程 | 比价自主完成；**下单前发确认卡片**：商品、总价、付款方式 |
| 做视频、创作 | 任务线程，带素材和成片预览 | 选题和发布前由用户拍板 |

### 长任务如何协作

接到长任务时，Jeeves 简要说明打算怎么做、预计在哪些节点汇报。执行中，常规步骤可以随情况自行调整。如果某项决定会实质改变已约定的目标、成本、权限或承诺，先请用户决定。一旦发现承诺的结果可能无法交付，就尽早说明哪里有风险、还能交付什么。

## 5. 对现有实现的影响

手机任务列表和 Mac Cowork 可查看同一执行会话。主聊天汇集任务通知和回执。按天浏览和搜索历史任务仍在规划中。
