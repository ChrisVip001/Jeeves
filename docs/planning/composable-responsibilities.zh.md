# 用聊天创建周期性委托的实施计划

[English](composable-responsibilities.md) | 简体中文

本计划处于实施中。产品入口沿用[主对话、工作与交付](../design/main-entry.zh.md)，执行边界沿用[技术架构](../architecture.zh.md)。每条委托归属于一个用户的一个 Runtime。一次定时检查可以直接完成，无需新开任务线程。

## 产品与执行边界

保存用户原话、稳定的委托 ID 和已确认版本。Rust 管理时间及时区、来源身份、证据字段、条件、产物、收件人、审批、期限、停止条件和单次预算。写作要求保留原文。聊天与「我的工作」展示从已校验字段生成的同一张卡，启用前明确显示时区和频率等默认值。只澄清会改变行为的歧义。模型可提出创建或修改建议，由人确认展示的版本。样例预览仅使用获准的读取能力，保留正式观察位置和首次命中机会，不产生投递。

| 用户可组合已启用的能力 | 工程侧一次实现的能力 |
| --- | --- |
| 日期、频率、时间范围、来源子集、篇幅、文风和已有目的地 | Rust 日期窗口、只读连接器绑定、证据身份和确定性筛选 |
| 每周汇总、到期结束、第一次观察到降价只提醒一次 | Rust 金额与币种比较、稳定商品身份、运费核验和持久化首次命中状态 |
| 只留本地草稿，或看过正文再发给已核实的群 | 平台适配器、必要的执行沙箱、账号与收件人解析、临发送校验和回执核对 |

无法观察的事实保留为未知。新增预订、购买或第三方写入动作，需要实现该能力并由人开启。私人来源限于原用户和被授权的受众。本地记忆失败时当前对话继续；业务来源缺失时展示不完整结果或跳过原因。网关路由到委托所属 Runtime。仅设备可读的资料等待该设备，并遵循委托的补跑策略。

## 阶段一 — 启用前核对委托定义

先接入已有人工登记入口。在 `protocol/src/protocol/v2.rs` 和 `protocol/src/export.rs` 增加只读定义核对方法。在 `jeeves-app-server/src/responsibility.rs` 让核对与登记共用规范化、校验逻辑，经 dispatch 和 `jeeves-ops/src/api/responsibilities.rs` 的已认证工作台接口返回规范化契约。启用时重新检查有效期、唯一标识和全部登记条件。反复核对不创建委托、唤醒或审批。`scripts/smoke-web.py` 经 HTTP 验证非法输入和登记结果与核对结果相同。这一步核对字段；带真实来源的样例预览在阶段三交付。

随后扩展契约，增加类型化来源、窗口、判定、产物、目的地和停止条件，单独保存可编辑的写作要求。在 `jeeves-state/migrations` 增加增量迁移，保存不可变版本并将每次触发绑定到对应版本。在旧数据库副本演练。编辑须提交预期版本，两个并发编辑只有一个生效，另一端看到冲突。重命名或改版保留触发身份。协议变更通过 `just write-app-server-schema` 生成两种 schema。

## 阶段二 — 完成单次执行闭环

扩展 `jeeves-state/src/responsibilities.rs`、`weekly_reports.rs`、既有 wake 与 completion 存储，以及 `jeeves-app-server/src/responsibility.rs`、`scheduler/` 和 `wake.rs`。认领计划时刻或稳定来源事件 ID 时，在同一事务绑定已确认版本。分别保留各委托的时区、夏令时和离线补跑语义；缺少可重放稳定 ID 的事件来源只提供定时观察。继续使用现有调度器和每租户本地存储。

分别记录观察、草稿、批准和送达。产出前核实来源身份和预算，外发前持久记录发送意图，最后校验当前版本、权限、期限、正文摘要、连接身份和收件人。成功时将本地终态、证据或回执、已消费的首次命中及活动记录原子提交。崩溃后结果未知的外发进入既有人工对账。暂停阻止新认领及未发出的旧批准，并单列已进入渠道的未知结果。恢复只解除故障自身造成的暂停。覆盖重复触发、补跑、暂停恢复、撤权、发送中断和终态事务失败；确定性读取可以全程零模型调用。

## 阶段三 — 主聊天创建与 Web 确认

在 `jeeves-app-server/src/interaction/{mod,decision}.rs` 从用户实际消息和已启用能力产生结构化建议。人工确认绑定已展示版本。Runtime 提供核对、样例、启用、修订、暂停、恢复和历史接口，模型工具无法自行启用或外发。在 `web/src/CoworkConversation.vue`、`web/src/ui/TaskCenter.vue` 中复用生成类型和现有审批卡，提供中英文界面。历史记录展示来源失败、未命中检查、完成回执及发送中断。打开卡片没有执行副作用。验收覆盖编辑对象有歧义、页面版本过期、缺少沙箱以及预览后启用。

## 阶段四 — 切换三项存量业务

先在隔离环境用保存的来源快照比对产物。逐条委托在同一事务记录旧身份、最后已认领位置、新执行入口；新旧入口在认领前都检查归属。已经受理的工作留给原入口收尾或转人工对账。新入口尚未认领时可恢复原归属；已经认领后，保留该记录，先核对外部结果，再决定下一次切换。在数据库副本验证备份与恢复后才能操作实际用户数据。旧入口在途清空后移除专用调度分支。

| 切换顺序与模块 | 映射及切换门槛 |
| --- | --- |
| 1. 周报。`responsibility.rs`、`weekly_report.rs`、`jeeves-state/src/weekly_reports.rs`、`jeeves-agent/src/verify_sources/weekly.rs` | 将 `weekly_report_json` 映射为研究工作区、允许的已存来源 URL、核验摘要和飞书收件人。保留委托 ID、最后时刻、wake key、草稿、待审批和回执。继续支持本地草稿及中断转人工核对。比对带来源正文，在等待批准时暂停或撤权，模拟发出后崩溃，用回环飞书服务确认没有第二次 POST。 |
| 2. 晨报。`scheduler/morning.rs`、`scheduler/fire.rs` 和 schedule completions | 只转换已启用晨报，保留时区、当地日期 08:00 身份、补跑策略及 outbox/notify 选择。保留零模型排版、逐项来源缺失说明和至多一次通知尝试。给已有日历读取增加显式当地日期范围，供后续自由组合。晨报 eval 比对夏令时、当天重启、邮件不可读、普通日程以及通知失败。 |
| 3. 比价。`interaction/price_watch.rs`、任务修订、观察及回执存储 | 保存任务与操作 ID、来源摘要、型号规格、币种运费、当前版本、期限、下次检查和历史。一次移交轮询权。保留暂停、完成及过期状态。历史价格凭证只证明观察。等于 ¥6,000 时不命中。旧阈值 ¥6,000 的检查返回 ¥5,800 前，用户改为 ¥5,500，预期无完成或外发。另测首次观察即低价、运费未知及投递结果未知后的重启。 |

复用 `just smoke-weekly-report`、`just eval-morning-briefing`、`just smoke-price-watch` 及恢复夹具。比对观察、收件人、草稿、回执和外部发送次数。

## 阶段五 — 第四项未预置需求与发布验收

在全新普通 Web 对话中说“每周五下午把下周会议和当前未完成任务整理成两段发到这个聊天，带来源”。在下个当地自然周边界内外各放一条会议，另放一条未完成和一条已完成任务。卡片展示周五下午实际采用的时间。换一种表达并改时间范围，仍使用相同能力。这段需求不得出现在内置模板、固定短语路由、生产提示词或任务专用分支里。

1. 连续预览两次。只有窗口内会议及未完成任务进入正文，分成两段，各有可解析的来源。预览不产生已启用订阅、正式游标、审批或外部消息。
2. 启用一次，将可控时钟推进至周五，重放同一触发并重新打开数据库。主聊天恰有一次可追溯交付，一条终态记录。核对来源快照与回执，并断言邮件和飞书均零发送。
3. 在对话中说“改到周四，只保留会议”。展示变更、确认新版本，推进到后续周四。原周五时刻和任务来源都不产生工作。在聊天中暂停，核对 Web 卡片并再跨一次到期时刻。恢复后只运行符合条件的未来时刻。
4. 分别保存确定性 Runtime/eval 结果、真实模型澄清与修订的对话记录，以及托管和自托管 Web 的验证结果。证据包含委托 ID、修订、计划时刻、来源引用、交付记录和外部尝试次数。执行 schema 漂移检查、`just check` 及迁移 smokes。三项切换和第四项对话通过后，把已落地契约写入双语正式文档并关闭计划。
